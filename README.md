## 何をしているか
| 部品 | 役割 |
|---|---|
| `scanner.py`（レーダー） | pump.fun の新コインを見張り、作成と同じ瞬間〜約1秒以内に買った財布（まとめ買い・狙撃ボット）を記録 |
| `desk/`（デスク） | 卒業（PumpSwap）して20分以上たったコインを8つの役割で審査し、練習売買する |
| `build_page.py` | スマホ用ページと `bots.json`（ボット財布一覧）を作る |

1時間ごとに GitHub Actions で自動実行：テスト → レーダー40分 ＋ デスク50分（同時） → ページ公開。

## デスクの8つの役割
Scanner（卒業コインを集める）／ Rug（詐欺チェック・データ不足は不合格）／ Risk（拒否権）／ Sniper（買い時）／ Whale（大口の動き）／ Hype（注目度※）／ Exit（売り）／ Desk Manager（最終判断と記録）
※X(旧Twitter)のデータは有料のため、取引の活発さ・SNSリンク有無などで代用。Rug・Riskの判断は覆せない。

## ルール（`desk/config.py`）
- 1回 $5〜10（資金の最大10%。設計書の40%は急落時の損失が大きすぎるため変更）
- スリッページ最大2%（x*y=k で事前に見積もり） ／ 損切り −6% ／ 同時保有 最大5件
- 1日の損失 $10 で、その日（ハワイ時間）は新規購入なし ／ 累計 $30 で完全停止
- 急落で損切りが効かない前提（−50%）で、残りの損失枠を計算してから買う
- 再開時に止まっていた時間を記録し、すぐに損切り条件を確認する（売値は実際の価格＝ごまかさない）
- Rug合格条件：mint/freeze権限の放棄、開発者 <5%、上位10（プール除く） <30%、流動性 ≥$10,000（実データで$30,000以上は卒業コインの10%しかなかったため引き下げ）、卒業後 ≥20分、LP ≥95%ロック/バーン、偽物でない、RugCheck危険判定なし、GoPlus（応答時）、**レーダー：作成ブロックのまとめ買い ≤2財布、ボット財布の保有 <5%**
- honeypot.is は Solana 非対応のため不使用 ／ Binance・Coinbase の価格差はミームコインに関係ないため不使用

## 操作
```
./run.sh              # ループ（既定50分）
./run.sh --once       # 1回だけ
./run.sh status       # 保有・現金・上限
./run.sh summary      # 成績
./run.sh rug <mint>   # 1コインの詐欺チェック
touch data/KILL       # 安全に停止（新規購入なし・ループ終了）
python -m pytest -q tests
```
記録：`data/desk/decisions.jsonl` と `data/desk/desk.sqlite`（すべての判断と理由）。状態：`data/desk/state.json`（再起動しても続きから）。

## 本番（実際のお金）について
未実装です。`execute_live_order()` は常に拒否します。本番にするには、専用ウォレットと**出金権限のない**キーを用意したうえでの明示的な承認が必要です。
また GitHub Actions は1時間ごとに数分〜十数分止まるため、本番では常時動くサーバー（VPS）が必要です。

## 設定
- `RPC_URL`（GitHub の Secrets・任意）: Helius などの Solana RPC。未設定でも、キー不要の公共窓口（PublicNode → Solana公式）を自動で切り替えて使う。大口保有者の一覧が取れない窓口では RugCheck の保有者データで代用
- Helius 無料枠（月100万クレジット）は、レーダーとデスクの合計で90万を超えると自動停止
